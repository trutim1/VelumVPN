# Участие в Velum

Этот документ предназначен для нового публичного репозитория клиента после
утверждения владельцем исходников и корневой LICENSE. Сам шаблон прав на код
не предоставляет. В release-only репозитории принимаются только изменения
присутствующих документов/метаданных, не закрытого клиентского кода.

## Предложение изменений

1. Для ошибки или идеи создайте issue без конфигураций и персональных данных.
2. Сделайте fork публичного клиентского репозитория и отдельную ветку в своём fork.
3. Внесите небольшое самостоятельное изменение, добавьте целевые тесты.
4. Откройте pull request в клиентский репозиторий и опишите результат проверок.
5. Дождитесь review владельца. Прямые push/admin-права участникам не требуются.

Название продукта в интерфейсе не доказывает наличие туннеля. Не добавляйте
обещаний подключения, kill switch, отсутствия утечек либо production-готовности
без воспроизводимых сетевых испытаний на соответствующей ОС.

## Локальные проверки

Требуются Rust edition 2024, Node.js/pnpm и системные зависимости Tauri для ОС.
Ориентируйтесь на текущие lockfiles, а не на произвольные latest-зависимости.

```text
cd client
cargo test --locked --all-targets
cd app
pnpm install --frozen-lockfile
pnpm test:ui
pnpm build
cargo test --locked --manifest-path src-tauri/Cargo.toml --all-targets
```

Не запускать незнакомые ветки на машине с реальными VPN-профилями/ключами.
Изменения зависимостей и build scripts требуют отдельного review перед запуском.
Сетевые тесты проводить только в изолированной лаборатории, не на рабочем VPN.

## Секреты и лицензии

- Не прикладывайте `.env`, `.conf`, `.vpn`, private/preshared keys, токены, дампы
  хранилища, реальные endpoint/peer/account/subscription данные и закрытые логи.
- Используйте явно синтетические fixtures. Новые внешние компоненты должны иметь
  зафиксированные версии, происхождение, тексты лицензий и notices.
- Сохраняйте notices сторонних авторов; новый код предоставляйте по действующей
  LICENSE репозитория. Изменение лицензии не входит в обычный PR.
- Уязвимости сообщайте приватно по SECURITY.md, не через публичный issue.

## CI и review

PR из fork не получают deployment/signing/payment/SSH-токены. Не использовать
`pull_request_target`, privileged/self-hosted production runners, скачивание
артефактов из чужих workflows с последующим исполнением или автоматическую
публикацию по PR. Проверки используют `pull_request`, read-only permissions,
непередаваемые секреты и SHA-pinned actions. Шаблон metadata-review не запускает
код PR и не заменяет тесты клиента. Публикация releases выполняется владельцем
после отдельного review точного коммита, состава и контрольных сумм.
